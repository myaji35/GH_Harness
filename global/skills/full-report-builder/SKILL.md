# 풀버전 보고서 빌더 (Full Report Builder)

> **왜 이 스킬이 있나 (2026-07-19)**: 대표님이 "충분히 하라"는데 절제된 결과를 반복해서 냈다.
> "이걸로 수만 불 받을 수 있겠냐"는 지적을 세 번 받았다. 매번 빼먹으므로 규율을 코드로 박는다.
> **이 스킬을 호출하면 아래 체크리스트를 todo로 만들고 전부 통과할 때까지 완료 보고 금지.**

---

## 0. 자기 검열 (착수 전 반드시 출력)

> *"내가 지금 엔진 숫자를 예쁘게 배열만 하려는가? → 그건 계산기지 보고서가 아니다."*
> *"클라이언트가 이 숫자만 보고 업무에 적용할 수 있는가? → 없으면 해설이 빠진 것이다."*
> *"이걸로 수만 불 받을 수 있는가? → No면 아직 미완성이다."*

---

## 1. 절대 규율 (대표님 지적에서 확정)

### ① 숫자는 반드시 해설한다 — 이게 보고서의 정의
- **모든 표·차트 아래에 "이 숫자가 무슨 뜻인가 → 그래서 당신은 무엇을 하면 되는가"** 문단을 붙인다.
- 숫자만 있고 해설이 없으면 그건 보고서가 아니라 데이터 덤프다.
- 대표님 원문: *"숫자를 해설해 주는 게 보고서지. 클라이언트가 숫자만 보면 업무에 적용할 수 있을까?"*

### ② XimTier의 진짜 실력을 부각한다 — 이게 고객 전환의 핵심
- 보고서 안에 **"왜 XimTier인가"** 섹션 필수. 일반 AI·통계 도구와의 대조표.
- 부각할 5가지 실력 (CLAUDE.md §1-B 근거):
  1. **오차 0 재현** — 분석엔진 실행값과 오차 0, 발급번호·해시로 감사 가능
  2. **통제 가능/불가 구분** — 실제로 바꿀 수 있는 변수만 처방 (행동 엔진)
  3. **교차 검증** — 기여율 × 구간격차로 그럴듯하지만 틀린 답 제거
  4. **책임질 수 있는 문서** — "AI가 그랬다"가 안 통하는 B2G에서 진본검증
  5. **반복 사이클** — 한 번 쓰는 도구가 아니라 실행→재측정→재처방
- 대표님 원문: *"XimTier 진정한 실력이 무엇인지를 부각해야지 고객이 되지 않겠니."*

### ③ 밀도 — "충분히" 채운다. 절제 금지
- **한 주제가 1페이지를 넘어도 된다.** (대표님 확정) 억지로 한 장에 욱여넣지 말 것.
- **빈 페이지(50% 헐렁) 금지.** 내용이 자연스럽게 흐르되 여백만 남기지 않는다.
- 목표: 데이터 나열 버전 대비 **최소 3배 이상의 내용** (해설·맥락·실행설계로 채운다).
- ⚠️ **여백·큰 폰트로 페이지 수 부풀리기 금지.** 양은 "채워서" 늘린다. 이건 사기의 반대.

### ③-B 분량 — "충분히"의 실제 기준 (2026-07-19, 여러 번 지적받음)
- **대표님이 "양이 부족하다"를 3번 이상 지적했다.** 데이터 나열판(약 2,600자)의 **8배 이상(20,000자~)**, 목표는 **5만 자급**.
- 근거: 맥킨지 클라이언트 산출물은 분석 섹션만 50+장, 공개 예시 220페이지(웹 확인). "10페이지 만들었다"에 취하지 말 것 — 헐렁하면 페이지 수는 무의미.
- **분량을 늘리는 정직한 방법 = 재료 소진.** 아래 순서로 안 쓴 데이터를 다 쓴다:
  1. **whatif를 기여 변수 3개가 아니라 통제가능 변수 전부(9개+)로** — override 함정 주의(x_vars 정확명)
  2. **5분위 x_means 전체 변수(17개+) 구간별 거동** — Q1→Q5 변화율 + 증가/역설/무관 자동 분류
  3. **변수 하나하나 개별 프로파일(Deep Dive)** — 23변수를 5P 축별로 묶어 각 변수마다 소절(분포+구간거동+기여+시나리오+해설). 이게 분량의 최대 광맥.
  4. **각 변수 미니 대시보드** — 텍스트 소절을 넘어 변수별 5분위 5구간 전체표 + whatif 전체 시나리오표까지 펼치면 5만 자 도달.
- ⚠️ **재료가 남았는데 "완성" 보고 금지.** report_result의 quintiles·stats·x_contrast·whatif_scenarios·quintile_trends·var_profiles를 다 소진했는지 확인.

### ④ "1주제 1페이지"는 슬라이드 규칙이지 문서 규칙이 아니다 (팩트체크 완료)
- 맥킨지 "one message per slide"는 **발표 덱(PPT)** 규칙. 글 보고서엔 적용 안 됨.
- 근거: deckary.com/blog/consulting-slide-standards — "the rule applies specifically to presentation slides, not written reports."
- 문서에서 지킬 것은 **Pyramid Principle(결론 먼저) + Action Title(제목=결론문장) + So-What**뿐. 페이지 밀도는 내용이 정한다.

## 2. 반드시 담을 섹션 (서사 4요소 + 실력 + 실행)

계획서 `docs/report-upgrade-plan.md` §1.5·§3의 구조. 순서 고정:

| # | 섹션 | 핵심 (Action Title로) | 데이터 소스 |
|---|---|---|---|
| 표지 | Cover | 프로젝트·발행주체(XimTier 컨설팅사업부) | domain, issue |
| 01 | Executive Summary | "X가 Y를 지배한다" (결론 먼저) | report.summary, contrib |
| 02 | 고객 상황 (Situation) | "같은 조건에서 N배 벌어진다" | profile, quintiles, stats |
| 03 | 접근·노력 (Approach) | "N개 변수·다중 알고리즘 자동학습" | profile, engine |
| 04 | 성과 동인 (기여도) | "무엇이 Y를 만드는가" + **해설** | actions/contrib |
| 05 | 구간 분석 (5분위) | "고성과 vs 저성과는 뭐가 다른가" + **격차표+해설** | quintiles, x_contrast |
| 05.7 | **구간별 변수 트렌드** | "고성과 구간은 어떤 변수가 다른가" (17변수 Q1→Q5) | quintile_trends |
| 05.5 | **Why XimTier** | "왜 이 답을 믿어도 되는가" (대조표) | ★ 필수 |
| 06 | 실행 처방 + 로드맵 | "무엇을 언제" (순서·단계·이유) | actions |
| 06.5 | **What-if 시나리오** | "변수 X% 조정 → 매출 Y%" + 포화/임계점/역효과 자동해설 | whatif_scenarios (9변수+) |
| 07.5 | **Deep Dive 변수별 심층분석** | "변수 하나하나를 뜯어본다" (5P축별 23변수) ★분량 최대광맥 | var_profiles |
| 07 | 객관성·한계 (Rigor) | "믿는 근거 + 숨기지 않는 한계" | grade, profile |
| 08 | 방법론·데이터 명세 | 5P·모델·변수 전체 통계표 | stats(전체) |
| 검증 | Verification | 발급번호·해시·진본검증 | issue |

## 3. 실행 절차

1. **재료 총동원** — 엔진에서 report·quintiles·profile·whatif·x_contrast 전부 실호출.
   - dataset_id는 `Project.graph.dig("dataset","dataset_id")`.
   - report_result에 `quintiles·profile·stats·x_contrast` 확장 저장 (없으면 표가 빈다).
   - ⚠️ **whatif override 함정 (해결됨 2026-07-19)**: override 키는 **x_vars(기여 변수)의 정확한 이름**이어야 한다(`engine_pro.py:whatif_multi`의 `if k in mod.columns`). Y후보 변수(방문객수·객단가 등)를 넣으면 x_vars에 없어 무시되고 delta 0이 된다. → **actions의 var(기여 변수)로 시뮬하라.** 각 변수를 mean 기준 ±10/±20%로 5수준 배치 호출.
   - **whatif 시나리오 = 수만불급의 핵심.** delta 패턴을 읽어 자동 해설: 포화(+10과 +20이 비슷)/임계점(+20이 훨씬 큼)/역효과(+10이 음수)/점진. "케이블광고비는 10%까지만, 신문은 빼라" 같은 처방이 여기서 나온다.
2. **뷰**: `ximtier_gateway/app/views/reports/full.html.erb`, `?view=full`로 렌더.
   - `min-height:297mm` 강제 금지 (내용 흐르게). 여백 축소, 폰트 ~11.5px, 표·차트 밀도.
   - 모든 수치는 엔진 실호출값. LLM이 지어낸 숫자 금지 (오차 0 규율).
2-B. **재료 확장 데이터 생성** (분량의 원료, ③-B):
   - `quintile_trends`: 5분위 x_means에서 변수별 Q1→Q5 배열+변화율 (17변수)
   - `whatif_scenarios`: 통제가능 변수 전부(9개+)를 mean 기준 ±10/±20% 5수준 배치 시뮬
   - `var_profiles`: p5map으로 변수를 5P축 분류 + stat/trend/scenario/contrib 통합 (23변수, X축 순 정렬)
   - 전부 `Project.report_result`에 저장 → 뷰가 읽음. 저장 안 하면 섹션이 빈다.
3. **검수 (완료 조건)**:
   - [ ] **텍스트량 20,000자 이상** (데이터 나열판의 8배). 목표 5만 자급 (규율 ③-B)
   - [ ] **재료 소진 확인** — quintiles·stats·x_contrast·whatif_scenarios·quintile_trends·var_profiles 다 썼나
   - [ ] 모든 표·차트에 해설 문단 있음 (규율 ①)
   - [ ] "Why XimTier" 섹션 있음 (규율 ②)
   - [ ] 빈 페이지(50% 헐렁) 없음 (규율 ③)
   - [ ] 자기검열 3문항 통과: "수만 불 받을 수 있는가?" = Yes
4. **화면 확인** — `open`으로 pane에 띄워 대표님이 눈으로 밀도 확인.

## 4. 하지 말 것

- ❌ 엔진 숫자만 배열하고 "완성" 보고 → 계산기지 보고서 아님
- ❌ 해설 없는 표·차트 → 클라이언트가 적용 못 함
- ❌ XimTier 실력 부각 생략 → 고객 전환 안 됨
- ❌ "1주제 1페이지" 강제로 헐렁하게 → 슬라이드 규칙 오적용
- ❌ 절제된 결과 후 되묻기 → "충분히"라고 했으면 최대로 만든다
- ❌ 여백·큰 폰트로 페이지 부풀리기 → 채워서 늘린다
- ❌ **재료 남았는데 "완성" 보고** → var_profiles·whatif 전변수·5분위 트렌드 다 소진 전엔 미완성 (2026-07-19 여러 번 지적)
- ❌ **20,000자 미만인데 "맥킨지급" 자칭** → 맥킨지 클라이언트물은 50+장. 분량이 절반이면 절반짜리
