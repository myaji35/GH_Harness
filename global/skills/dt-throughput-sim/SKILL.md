# Digital Twin Throughput Simulation (처리량 적절성 평가)

## Overview

디지털 트윈에서 "장비 대수·속도가 하루 처리량에 충분한가"를 정량 평가하는 틀. 스마트팜 DT에서 캐리어 2대의 누리셀 처리능력을 주기 25/30/50일로 재계산하며 확립했다.

**핵심 원칙**: 하루 목표는 재고÷주기로 나오고, 처리능력은 **실측 사이클타임 + 이론(이동거리) + 보수(실환경 배수)** 3중으로 대조한다. 단일 숫자를 믿지 마라.

## When to Use

- 트윈 fleet(AGV/캐리어/로봇)이 일일 목표를 감당하는지 판단할 때
- 장비 대수·가동시간 최적화 논거가 필요할 때(사업계획 근거)
- "처리량이 병목인가, 아니면 다른 게 병목인가" 가릴 때

**When NOT**: 실측 운영 데이터가 이미 있을 때(그땐 실데이터 직접 분석), 단일 장비 단순 작업.

## 계산 틀 (4단계)

### 1. 하루 처리 목표 = 재고 ÷ 주기
```
dailyDemand = 총재고(NDRUM) / 재배·회전주기(일)
```
주의: **주기가 길수록 하루 목표는 줄어든다**(50일→58셀, 25일→115셀). 직관과 반대라 헷갈리기 쉬움. 코드에 있는 실제 KPI(예: "오늘 수확 N")와 대조해 타당성 교차확인.

### 2. 사이클타임 3중 확보 (단일값 금지)
| 출처 | 방법 | 신뢰도 |
|---|---|---|
| **실측** | 라이브 트윈에서 `cycleTimes` 수집 (Date.now 차분) | 이동거리·속도 반영된 물리값 |
| **이론** | 평균 이동거리 ÷ 속도 + 작업(픽업/인계) 고정시간 | 하한(이상적) |
| **보수** | 실측 × 2~3 (연출시간 배제 + 실제 기구 동작 가중) | 실환경 근사 |

라이브 실측 시 **함정**: 시뮬 사이클타임엔 애니메이션 연출 시간(포크 5s 등)이 포함돼 실제보다 빠를 수 있음 → 반드시 보수 시나리오를 함께 제시.

### 3. 처리능력 → 배율
```
캐리어당/시간 = 3600 / cycleSec
하루능력 = 캐리어당/시간 × 대수 × 가동시간
배율 = 하루능력 / dailyDemand
목표충족 최소가동 = dailyDemand / (캐리어당/시간 × 대수)
```

### 4. 판정 + 결론틀
- 배율 ≥3 여유, 1.5~3 적정, 1~1.5 빠듯, <1 불가
- **반드시 "1대 운용 시" 여유도 함께 계산** → 대수 최적화 논거

## 결론틀: "능력 vs 병목 분리" ⭐

처리능력이 크게 남으면(예: 20배) 결론은 "충분"이 아니라 **세 가지를 분리해 보고**:
1. **능력 과잉의 의미** — 100% 무정지 가정. 실제론 충전·정비·통로대기로 실효율 하락.
2. **가동시간의 진짜 목적** — 처리량이 아니라 품질·적기대응(상시 수확). 능력이 남으면 가동시간은 인건비·품질 기준으로.
3. **진짜 병목 지목** — 처리량이 병목이 아니면 무엇인가?(예: 좁은 통로 충돌·정체) → 다음 작업 우선순위로 연결.

## Common Mistakes

| 실수 | 결과 | 해결 |
|---|---|---|
| 주기 길수록 목표 늘 거라 가정 | 방향 반대 | 재고÷주기 (주기↑→목표↓) |
| 실측 사이클타임만 신뢰 | 연출시간 포함돼 과대평가 | 이론+보수 3중 대조 |
| "능력 충분" 단정 | 병목 놓침 | 능력/가동목적/병목 분리 보고 |
| 대수 최적화 누락 | 과잉투자 | 1대 운용 여유도 계산 |
