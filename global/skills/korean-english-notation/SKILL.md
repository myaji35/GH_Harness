# /korean-english-notation

한국어 공문서·법인서류·보고서에서 **영문표기를 한글 우선 + 괄호 병기** 형식으로 통일하는 규칙.

## 핵심 규칙

### 1. 일반 영문 → `한글표기(영문)`
원래 영문이 고유명사/일반단어이면 한글표기를 앞에 두고 괄호 안에 영문 원문을 넣는다.

| Before | After |
|--------|-------|
| XimTier | 심티어(XimTier) |
| SaaS 제공업 | 서비스형 소프트웨어(SaaS) 제공업 |
| Han iL | 한일(Han iL) |

### 2. 약어 영문 → `한글표기(풀네임)`
영문이 **머리글자 약어(acronym)**이면 괄호 안에 **한글 약어가 아니라 영문 풀네임**을 넣는다.
(단, 한글 정식명칭이 이미 널리 쓰이면 `한글정식명칭(영문 풀네임, 약어)` 형태도 허용)

| 약어 | 권장 표기 |
|------|-----------|
| AI | 인공지능(Artificial Intelligence, AI) |
| XAI | 설명가능 인공지능(eXplainable AI) |
| API | 응용 프로그래밍 인터페이스(Application Programming Interface, API) |
| GIS | 공간정보시스템(Geographic Information System) |
| SNS | 소셜 네트워크 서비스(Social Network Service) |
| MCP | 모델 컨텍스트 프로토콜(Model Context Protocol) |
| IROS | 인터넷등기소(Internet Registry Office System) |
| SaaS | 서비스형 소프트웨어(Software as a Service) |

### 3. 이미 `한글(영문)`으로 되어 있으면 그대로 둔다
예: `인공지능(AI)`처럼 이미 한글이 앞에 있고 괄호에 영문이 있으면 재작업 금지. 다만 약어 규칙(2)에 따라 풀네임 병기가 더 정확하면 풀네임으로 보강할 수 있다(문서 목적에 따라 판단).

### 4. 회사 정식 상호·법정 표기는 원문 우선
등기부·정관의 `주식회사 심티어 (XimTier Co., Ltd.)`처럼 **법적 정식 상호**는 이미 확정된 표기이므로 임의 변경 금지. 이 규칙은 본문 서술·업종 기재·설명문에 적용한다.

### 5. URL·이메일·계좌·코드값은 제외
`www.ximtier.com`, 전자납부번호, 계좌번호, HTML class/CSS 속성 등은 영문표기 변환 대상이 아니다.

## 적용 대상 판별
- **적용**: 본문 서술문, 업종·목적 기재, 인명 로마자 병기, 기술용어 약어
- **제외**: 법정 정식 상호, URL/이메일, 코드/CSS, 숫자+영문 식별자(계좌·납부번호), 작성요령 예시 placeholder

## 워크플로우
1. 대상 문서에서 영문 토큰 추출 (CSS/코드/URL 제외)
2. 각 토큰을 규칙 1~5로 분류 (일반 / 약어 / 이미완성 / 정식상호 / 제외)
3. 약어는 표준 풀네임 확인 후 병기
4. HTML/텍스트에서 치환 (정식상호·예시 placeholder 보존)
5. 변환표를 사용자에게 보고 후 확정

## 자가 점검
- [ ] 법정 정식 상호를 임의 변경하지 않았는가
- [ ] 약어는 풀네임을 병기했는가 (한글약어 아님)
- [ ] 이미 `한글(영문)`인 것을 중복 변환하지 않았는가
- [ ] URL·계좌·코드·작성요령 예시를 건드리지 않았는가
