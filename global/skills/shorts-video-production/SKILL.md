# shorts-video-production — 영상 제작 자가규율 게이트

## 발동 즉시 (사용자에게 *반드시* 출력)

영상 작업 트리거가 발동되면, **다른 어떤 작업보다 먼저** 다음 자가점검 11개 + 12번을 명시적으로 출력하고 각 항목의 통과/결손/모름을 표시한다. 결손이 1개라도 있으면 **작업 진행 차단** 또는 *사용자에게 명시 컨펌 요청* (조용한 진행 절대 금지).

```

[원본 12개 — 시각/대본/모션/검증]
⓵  시각 콘텐츠 ≠ 메타데이터 — 산출 mp4를 Vision으로 시각 검증할 계획?           [ ✓ / ✗ / 미정 ]
⓶  한국어 수사 — TTS 텍스트가 normalizeForKoreanTts() 통과?                    [ ✓ / ✗ / 미정 ]

⓸  9:16 풀 활용 — 흰띠/검정띠 없음 + 배경 영상 길이 ≥ 영상 길이?                    [ ✓ / ✗ / 미정 ]

⓼  자막 = HyperFrames(GSAP) 모션 — 정적 PNG 금지                              [ ✓ / ✗ / 미정 ]
⓽  컷 빈도 ≥ 0.5/초                                                         [ ✓ / ✗ / 미정 ]
⓾  멀티컷 = 다른 환경 prompt + 다른 seed                                      [ ✓ / ✗ / 미정 ]
⓫  사전·사후 자동 검증 게이트 호출 (script-validator + video-postcheck)            [ ✓ / ✗ / 미정 ]
```

## 룰

### Rule 1 — 게이트 통과 없이 산출 보고 금지
14개 항목 중 단 한 개라도 ✗ 또는 미정이면, *그 결손을 명시한 채로 사용자에게 컨펌받기 전*까지 영상 산출을 "성공"으로 보고하지 않는다.
산출 mp4가 실제로 만들어졌더라도 결손이 있으면 **"산출은 됐으나 N개 항목 결손, 진짜 영상이 아닙니다"** 형식으로 보고한다.

### Rule 2 — ffprobe 메타만으로 "검증 통과" 보고 금지
ffprobe로 코덱/해상도/길이만 확인하고 "검증 통과"라 보고하면 lessons #1 직접 위반. 반드시 다음 중 하나 이상 추가:
- ffmpeg로 프레임 1~3장 추출 → Read 도구로 시각 확인
- `pipeline/_shared/orientation-validator.ts` 호출 (Gemini Vision)
- `pipeline/_shared/video-postcheck.ts` 호출 (구현 시)
- 사용자에게 영상 직접 시청 후 피드백 요청

### Rule 3 — 결손 항목 처리 절차
| 결손 종류 | 처리 |
|---|---|
| 진짜 상품 이미지 부재 (#3, #14) | API 키 시도 → 실패 시 사용자에게 직접 다운로드 요청. **자동 진행 금지**. sample/플레이스홀더 이미지로 대체 절대 금지 |
| TTS 부재 (#15, ⓭) | API 키 점검 → 빈 키면 사용자에게 명시 보고. v17 시절 mp4에서 audio 추출 시도 가능. composition HTML에 `<audio data-start data-duration data-track-index>` 트랙 누락 점검 |
| 배경 영상 < 영상 길이 (#4) | 사용자에게 알리고 옵션 제시 (loop / 검정 padding / 짧게 trim). 검정 padding은 lessons #4 위반이라 *명시 컨펌 필수* |
| 한글 폰트 fallback (Ⓕ) | Pretendard CDN @font-face 직접 박기 (자동 가능). HyperFrames doctor의 폰트 매핑 경고 무시 금지 |
| script-validator/video-postcheck 미구현 (#11) | "검증 모듈 미구현 — 사후 자동 게이트 없음" 명시 후 사용자가 위험 감수 동의 시만 진행 |
| 타겟 페르소나 미스매치 (#13) | 채널 brand-dna `target_audience` (성별/연령/맥락) 읽고 배경 prompt와 비교. 미스매치 시 **즉시 폐기** + 사용자 보고. 강아지/여성/노인 등 임의 영상 사용 금지 |
| 상품 이미지 잠깐 노출 (#14) | composition HTML에 별도 `<img>` 트랙으로 영구 또는 ≥70% 시간 노출. 0.5~1초만 등장 후 사라지는 패턴 금지 |
| CTA 클릭 경로 부재 (#16) | 영상 끝 시각 클릭 유도 요소(커서/탭 애니메이션) 추가 + 발행 단계 핀고정 댓글/Bio 링크 자동 생성 검증. 어필리에이트 query param 부착 확인 (RULE_011, RULE_019) |
| HyperFrames lint error (Ⓛ) | 0 error 통과 못하면 render 차단. error 종류별 자동 fix 시도 (class="clip" 추가, 트랙 분리, repeat:-1 → 유한 반복 등) |
| timeline ID 불일치 (Ⓟ) | `data-composition-id`와 `window.__timelines[키]` 일치 확인 (HyperFrames runtime이 기본 "main" 사용) |

### Rule 4 — TTS 작업 시작 전 점검
- TTS 텍스트는 `normalizeForKoreanTts()` 통과 필수
- `channels/{name}/voice.md` 톤 가이드 + `brand-dna.json` `tts_voice_id` 확인
- API 키 빈 상태이면 *진행 금지* — 사용자에게 명시 보고
- composition HTML에 `<audio data-start data-duration data-track-index>` 트랙 누락 점검

### Rule 5 — composition lint 필수
HyperFrames render 전 `npx hyperframes lint <dir>` 호출. 0 error 통과 못하면 차단.

### Rule 6 — 작업 끝나기 전 21개 자가점검 다시 한 번 출력
산출 직후 자가점검을 **다시 출력**해서 작업 시작 시점과 종료 시점의 통과/결손 표를 비교 가능하게 한다.

### Rule 8 — 상업성 Rubric 90점 미만 자동 반복 (대표님 2026-05-08 직접 지시) ⭐⭐⭐⭐

**절차**:
1. 영상 산출 직후 `docs/commercial-quality-rubric.md` 10축 자동 채점 (`pipeline/_shared/commercial-grader.ts` 호출)
2. 점수 < 90이면:
   - 결손 항목 우선순위 식별
   - 자동 fix 시도 (누끼/Seedance/실사 stock/Edge TTS rate 등)
   - 재렌더 → 재채점
3. 최대 5회 루프, 5회 후에도 < 90이면 사용자에게 명시 보고 + 작업 차단
4. **자가점검 21개 통과 + Rubric 90점 둘 다 만족해야 사용자에게 "영상 산출"로 보고**

**금지**:
- ❌ 자가점검 점수만 보고 (시청자 관점 누락)
- ❌ 누끼 안 된 흰배경 사각형 = ⓮ 만점 부여
- ❌ CSS 그라디언트 = "멀티컷 4구간" 채점
- ❌ 90점 미만인데 사용자에게 그대로 보여주기
- ❌ "다음 세션에서 90점 도달" 미루기 (이번 세션에서 루프 발동 필수)

**근거**: 2026-05-08 대표님 4번째 같은 지적 — "상업성 영상에 대한 검수내용을 자체적으로 만들어서 검수하고 90점 이햐는 반복 점검해서 구현하자."

### Rule 7 — 반드시 자체 검수하고 보여줘 (대표님 2026-05-08 직접 지시) ⭐⭐⭐
**사용자에게 영상 보여주기 전에 AI가 직접 자체 검수 완료**. 카운트가 아닌 점수.

**자체 검수 절차 (영상 산출 직후 필수, 사용자 보고 전)**:

1. **메타 검증**: ffprobe로 비디오/오디오 트랙 코덱·해상도·길이·sample_rate·channels
2. **음성 검증** (절대 빠뜨리지 말 것):
   - `ffmpeg ... -af silencedetect=noise=-30dB:d=0.5,volumedetect`
   - 무음 구간 합계 / 영상 전체 길이 = 무음 비율 < 30%
   - mean_volume / max_volume 측정
   - **메타 length ≠ 실제 음성 length 발견 시 결손 명시 필수**
3. **시각 검증**: 프레임 5장 이상 (0초 / 1.5초 / 3초 / 영상 길이/2 / 영상 끝-0.5초) → Read 도구로 직접 시각 확인
4. **항목별 5점 채점** — 21개 자가점검 (#1~#17 + Ⓐ Ⓕ Ⓛ Ⓟ)
   - 5점: 완벽 통과
   - 3~4점: 부분 통과 (구체 결손 명시)
   - 0~2점: 결손 (수정 방향 명시)
5. **가중치**: 어필리에이트 본질 4개 (⓭ ⓮ ⓯ ⓰) × 2
6. **95점 환산**: v17a 95점 기준 = (가중 합계 / 가중 만점) × 100
7. **결손 우선순위 3~4개**를 다음 수정 우선순위로 명시
8. **사용자 보고**: 채점표 + 결손 + 다음 단계 동시

**금지 패턴 (사용자 지적 받기 전에 자가 검열)**:
- ❌ "통과 X / 결손 Y" 카운트만 (점수 없음)
- ❌ "ffprobe 메타 통과 = 영상 통과" (lessons #1 위반)
- ❌ "결손은 다음 세션에서" (이번 세션에서 명시 필수)
- ❌ "사용자가 보고 판단해주세요" (책임 전가)
- ❌ "통과 14 / 부분 2 / 결손 3" 형식의 불완전 보고 (DEMO-002 첫 보고에서 했던 실수)

**근거**: 2026-05-08 대표님 직접 지시 — "반드시 자체 검수하고 보여줘 꼭 기억하고 실행해."
근거 사례: DEMO-002 첫 보고 "통과 14 / 부분 2 / 결손 3" → 대표님 지적 후 정직 채점하니 65/100 (가중 58.3, E 등급). TTS 메타 6초 vs 실제 음성 2.58초(70% 무음) 사후 발견 — 자체 검수 안 했으면 사용자가 직접 영상 봐서야 발견했을 결손.
