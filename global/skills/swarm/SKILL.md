# Swarm (병렬 작업자 → 보고서 하나)

> 출처: open-pstack `swarm` (MIT, NOTICE.md). GH_Harness 규칙에 맞게 옮김.

할 일 목록에 단계별 항목을 먼저 연다: 1 틀 2 펼치기 3 모으기 4 보고.

## 실행 수단 (원본의 provider-dispatch·모델 시트 대체)

| 수단 | 언제 | 비고 |
|---|---|---|
| `Agent` 병렬 스폰 | **기본** | 한 응답에서 동시에 띄운다. **동시 3개 이하**. 읽기·조사는 `Explore`, 쓰기가 필요하면 `general-purpose` |
| Codex CLI | 다른 모델 관점이 필요한 레이스 팔 | `codex exec -s read-only -C <repo> -o <출력파일> "<브리프>"` (읽기 전용). 쓰기 작업은 저장소당 Codex 1개 규칙 때문에 전용 worktree 에서만 |
| `Workflow` 도구 | **대표님이 명시적으로 요청할 때만** | 예: "워크플로우로 돌려". 요청 없이 쓰지 않는다. 쓸 때는 `workflow-authoring` 스킬을 먼저 읽는다 |

- N 이 3 을 넘으면 3개씩 차례로 돌린다(물결). 하네스 background 정책(동시 background ≤ 2, `background-track.sh claim`)이 걸리는 장시간 작업이면 그 한도를 따른다.
- 같은 파일·디렉터리를 동시에 고치는 작업자가 둘 이상이면 각자 `isolation: worktree`. 서로 다른 파일이거나 읽기 전용이면 worktree 를 쓰지 않는다.
- 코드 수정이 목적인 swarm 은 하지 않는다 — 코드 변경은 Codex 위임 규칙(저장소당 동시 1개)을 따른다. swarm 은 조사·검증·측정·탐색용이다.

## A. 틀

1. 완료 판정식과 swarm 이 돌려줄 산출물(보고서·표)을 적는다.
2. 모양을 고른다: 조각 분담, 같은 브리프 N개 레이스, 또는 섞기. 레이스·섞기면 띄우기 전에 선정 규칙을 정한다 — `first pass`(첫 통과), `rank all`(전부 순위), `best-of`(최고 하나).
3. 작업자 수단을 고른다(위 표). 모델 레이스면 팔마다 모델을 미리 적는다. 작업 성격에 맞게 effort 를 고른다(하네스 모드 테이블 기준, 즉흥 상향 금지).
4. 쓰는 작업자에게는 각자 전용 출력 경로를 준다. 커밋을 검증·측정하는 작업자에게는 정확한 SHA 를, 측정 브리프에는 방법(표본 수, 표본 하나의 정의, 순서)을 적는다. 작업자는 둘 다 결과에 기록한다.

## B. 펼치기

N 작업자를 한 번의 펼치기 단계에서 띄운다(Agent 는 `run_in_background`, Codex 는 Bash `run_in_background`). 장시간 작업자를 포그라운드 Bash 로 돌리지 않는다.

기본 브랜치가 아닌 곳에서 시작해야 하면 그 작업자 전용 worktree 에서 그 브랜치를 체크아웃하고 브리프에 worktree 경로를 적는다.

브리프는 그것만 읽어도 일할 수 있어야 한다: 목표, 범위, 맡은 조각·레이스 팔, 검증 방법, 보고 형식. 보고는 `PASS` / `ISSUES` / `BLOCKED` + 근거. 결함을 증명할 수 있는 작업자는 `ISSUES` 로 보고하고 증명 가능한 결함을 첫 번째만이 아니라 전부 적는다.

작업자가 탈락하면 N-1 로 진행하고 수단·모델·실패 사유를 적는다. 다른 수단으로 몰래 대체하지 않는다.

## C. 모으기

결과를 읽는다. 브리프가 요구한 SHA·방법을 기록하지 않은 결과는 버리고 그 작업자를 한 번 다시 띄운다. 두 번째도 빠지면 공백(gap)으로 적는다. 공백은 통과가 아니다. 커버리지면 모든 조각에 결과가 있어야 하고, 레이스면 미리 정한 선정 규칙을 적용한다. 작업자 원문을 그대로 붙이지 않는다.

## D. 보고 (한국어)

표 하나 + 결함 한 줄씩 + 공백·탈락 + (레이스면) 선정 규칙. 영어 결과는 한국어로 옮긴다. swarm 결과가 이슈 완료 근거가 되면 on_complete result 의 `proof[{cmd,exit_code,output}]` 에 작업자가 실행한 명령과 출력을 담는다.

## 다른 스킬과의 구분

- `arena`: 같은 산출물을 여러 후보가 만들고 **하나로 합친다**. swarm 은 합치지 않고 **보고**한다.
- `interrogate`: 변경 하나에 대한 멀티 모델 교차 검토 전용.
- RACE_MODE: 코드 구현을 provider 별 worktree 에서 경쟁 → 자동 채점 → 승자 머지(`race-dispatch.sh`/`race-judge.sh`).
