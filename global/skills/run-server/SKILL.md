# run-server — 디렉토리 번호 기반 3000번대 포트 실행

## 언제 쓰나
대표님이 **"서버 실행하자"**(또는 서버 띄워/앱 실행하자/run server 등)라고 하면 이 스킬로 실행한다.

## 핵심 규칙 (포트 산출)
**프로젝트 디렉토리명 앞 4자리 숫자를 찾아 3000번대로 변환한다.**

```
포트 = 3000 + (앞4자리 숫자 % 1000)
```

| 디렉토리명 | 앞 4자리 | 포트 |
|---|---|---|
| `0029_XimTier_ENG` | 0029 | **3029** |
| `0050_ShortsAffiliate` | 0050 | 3050 |
| `0123_Foo` | 0123 | 3123 |

앞 4자리 숫자가 없는 디렉토리에서는 실행 불가(에러). 반드시 `NNNN_` 형식 프로젝트 루트에서 실행.

## 실행 절차
현재 작업 디렉토리(또는 인자로 받은 프로젝트 경로)에서 아래 스크립트를 실행한다.
스크래치패드 경로가 있으면 환경변수로 넘겨 venv를 로컬 디스크에 두게 한다(외장 SSD AppleDouble 회피).

```bash
CLAUDE_SCRATCHPAD="<이 세션의 스크래치패드 경로>" \
  bash ~/.claude/skills/run-server/serve.sh "<프로젝트 루트, 생략 시 CWD>"
```

- 예: XimTier 실행
  ```bash
  CLAUDE_SCRATCHPAD="$SCRATCH" bash ~/.claude/skills/run-server/serve.sh \
    /Volumes/E_SSD/02_GitHub.nosync/0029_XimTier_ENG
  ```
  → 앞4자리 `0029` → 포트 **3029** → `http://127.0.0.1:3029/`

스크립트를 **`run_in_background: true`** 로 실행할 필요는 없다. 스크립트 자체가 앱을 nohup 백그라운드로 띄우고, 200 헬스체크가 끝나면 리턴한다(최대 90초). 다만 대형 앱은 부팅이 길 수 있으니 Bash 타임아웃을 120000ms 이상으로.

## 스크립트가 자동으로 하는 것 (검증환경 보정)
1. **포트 산출** — 디렉토리 앞4자리 → 3000번대.
2. **app.py 탐색** — 루트에 없으면 한 단계 하위에서 찾음(예: `XimTierV06191535P01/app.py`).
3. **venv 재사용/생성** — `CLAUDE_SCRATCHPAD/serve_venv_<NNNN>` (없으면 앱디렉토리 `.venv`). uv 우선, `pyproject.toml`로 의존성 설치.
4. **누락 의존성 보정** — `streamlit`, `pytz` 등 상습 누락 모듈 자동 설치. (새 상습 누락이 나오면 `serve.sh`의 `for m in ...` 목록에 추가.)
5. **포트 충돌 처리** — 3000번대 포트가 이미 LISTEN이면 기존 프로세스 종료 후 재실행.
6. **200 헬스체크** — 응답 확인 후 URL 안내. 부팅 중 Traceback/ModuleNotFound 감지 시 즉시 로그와 함께 실패 보고.

## 실행 후
- 성공: `✅ READY → http://127.0.0.1:<PORT>/` 안내. 대표님께 이 URL을 전한다.
- 실패: 로그 tail을 보고 원인(대개 누락 의존성)을 파악 → `serve.sh`의 보정 목록에 추가하거나 개별 설치 후 재실행.
- 브라우저 검증이 필요하면 Playwright/browse로 그 URL에 접속.

## 주의
- 이 스킬은 **백엔드 실행 + 검증환경 보정**까지만. 결과·UI 변경이나 기능 수정은 하지 않는다.
- 포트는 **디렉토리명이 결정**한다. 다른 포트를 원하면 대표님이 명시할 때만 오버라이드.
