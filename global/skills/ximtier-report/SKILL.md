# 심티어[산업별]보고서 — 50페이지 표준 템플릿

> 기획 근거: `0035_XimTier_ENG2/docs/심티어_산업별보고서_템플릿기획안_260729.md` (Fable 5 컨설턴트 기획 · Opus 5 실측 검수)
> 이 스킬은 그 기획안의 **실행 절차판**이다. 상세 구성표·카탈로그는 `references/` 참조.

## 0. 이 스킬이 푸는 문제

조선업 1차 보고서가 **"훌륭한 내부 검증 메모이자 실패한 고객 보고서"**였다. 근본 원인은 **정체성 미결정** — 내부 검증 기록과 고객 진단 보고를 한 문서로 섞었다. 이 스킬은 그 분리를 강제한다.

**한 문서 = 한 독자.** 독자는 고객사 현업 임원(생산본부장급) + 실무 팀장. 엔지니어링 상세는 부록과 내부 부속서로 격리.

## 1. 착수 전 확보할 것 — 산업 4개 주입점

50페이지 중 **고정 8p + 반고정 7p = 15p가 템플릿 자산**이고, 나머지 35p도 틀은 고정이다. 산업 교체는 아래 4개만 받으면 된다:

| # | 주입점 | 쓰이는 페이지 | 없으면 |
|---|---|---|---|
| ① | **5P 시트명·변수명** (성과/운영/투자/신호/환경 축의 산업 어휘) | p7·15 | 카드 산출 `p5_classify`에서 자동 도출 후 확인 요청 |
| ② | **성과지표 정의** (무엇을 Y로 볼 것인가 + 높을수록/낮을수록 좋은가) | p8·9·29 | **반드시 물어라** — 방향을 틀리면 처방이 통째로 뒤집힌다 |
| ③ | **현장 조치 번역** (변수 처방 → 월요일 아침에 할 일) | p35 | 고객 확인 필요로 표기하고 초안만 |
| ④ | **임팩트 단가** (시수당 종합원가 등) | p43 | `[가정]` 라벨 + "고객 데이터로 대체" 칸 |

②는 자문하지 말고 사용자에게 물어라. 나머지는 초안을 만들고 확인을 구한다.

## 3. 절대 규칙 5개 — 이걸 어기면 1차 보고서의 실패를 반복한다

### ① 답 먼저 (Pyramid Principle)
ES(p4–5)만 읽고 의사결정이 가능해야 한다. **전 페이지 제목은 메시지문(액션 타이틀)** — 명사구 금지.
- ❌ "2. DB연결 → ERD → 미션SQL"
- ✅ "심티어는 귀사 ERP를 가공 없이 그대로 읽습니다"

### ② 현업어만 (기술어 본문 0회)
`references/glossary.md`의 24개 대조표를 적용한다. 금지어가 본문에 나오면 위반:
`ISS-`, `P0/P1`, `validated`, `dataset`, `카티전`, `LIMIT`, `session`, 원시 R² 수치.
**예외**: 기획자 원문 인용은 번역하지 않는다 — 그 문장이 곧 현장어다.

### ③ 결함은 숨기지도 나열하지도 말고 자리를 배정한다
- 본문: p36(처방의 위험과 한계) · p41(보증하는 것/아직 아닌 것) — **고객어 운영 조건으로 번역**
- 부록 B: 미수정 기술 한계를 정직하게, 단 이슈번호 없이
- 내부 부속서(별도 파일): 이슈번호·등급·재현 조건
- **이미 수정된 결함은 결함이 아니라 "검증 절차가 잡아낸 항목"으로 서술**

### ④ 실재하는 시각물만
`references/visual-catalog.md`의 **실선 카드 산출물만** 쓴다. 점선(미완) 카드 산출물 사용 0건:
`table_graphic` · `document_graphic` · `thematic_map` · `wda_report` · `xai_var_confirm` 등 11장.
캡처는 **실조작 산출물만** — 크롭·주석 처리, 콘솔·버전 배지·이슈번호 노출 금지.

### ⑤ 가정과 실측의 분리
카드 산출 JSON 숫자는 **오차 0 전사**. 외부 숫자(단가·시장규모)는 `[가정]` 배지 + "고객 데이터로 대체" 칸 필수.
모의 데이터를 쓴 경우 **표지에 그 사실을 명시**한다.

## 4. 실행 절차

1. **산업·고객·성과지표 확인** — §1의 주입점 ②는 반드시 사용자에게 묻는다.
2. **카드 산출물 수집** — XimTier ENG2에서 실행한 결과(JSON·캡처)를 모은다. 없으면 어느 페이지가 비는지 먼저 보고한다.
3. **구성표 대조** — `references/50p-structure.md`로 페이지별 재료 유무를 표로 점검. **재료 없는 페이지는 만들지 말고 목록으로 보고**한다(분량 채우기 금지).
4. **HTML 작성** — `references/report-template.html`의 스타일을 상속. 표지 단색 `#16325C`, 마진 12mm×14mm, 머릿글·아랫글·쪽번호.
5. **PDF 생성** — Chrome headless `--print-to-pdf`(한글 겹침 방지 1순위). `report-pdf-builder` 스킬의 규칙을 그대로 따른다.
6. **품질 게이트 10항 통과** — `references/quality-gate.md`. 통과 못 하면 출고 금지.
7. **표지·본문 육안 검증** — PNG 추출해 백지·겹침 확인. 그 다음 `open`.
8. **아카이빙** — `archive_report.py`로 구글드라이브 + 옵시디언.

## 6. 산업 확장 시

새 산업(제약·물류·화학·반도체…)은 **재집필이 아니라 변수부 교체**다.
1. §1의 4개 주입점만 새로 받는다
2. `references/50p-structure.md`의 "교체" 열이 **고정/반고정**인 15페이지는 손대지 않는다
3. 산업 어휘 대조표를 `references/glossary.md`에 산업 섹션으로 추가한다 — 누적되면 그것이 도메인 노하우 자산이다
