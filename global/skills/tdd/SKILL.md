# TDD 버그 수정

> 출처: open-pstack `tdd` (MIT, NOTICE.md). GH_Harness 규칙에 맞게 옮김.

테스트 경로가 분명하고 싼 버그라면, 운영 코드를 바꾸기 전에 깨진 동작을 실행 가능한 형태로 만든다. 목표는 고치기 전 실패하고 고친 뒤 통과하는 좁은 회귀 테스트 하나다.

무리하게 테스트를 만들지 않는다. 넓은 테스트 장치 구성, 깨지기 쉬운 mock, 느린 E2E 인프라, 운영 전용 상태, 모호한 재현 절차, 무관한 fixture 대량 변경이 필요하면 새 테스트를 건너뛰고 가장 가까운 유용한 검증을 쓴다.

**하네스 규칙:** 테스트 작성과 버그 수정은 둘 다 코드이므로 **Codex 에 위임**한다. 나는 진단·지시·검수·실행을 맡는다. 같은 저장소에서 Codex 는 한 번에 하나이고, "실패 확인"을 끼워 넣어야 하므로 테스트 위임과 수정 위임은 **반드시 두 번에 나눠** 순서대로 한다. 상세: `opus-codes` 스킬.

## 절차

1. **버그 이해** (직접) — 의도된 동작, 현재 동작, 영향 경로, 가장 작은 관찰 가능한 재현을 정한다.
2. **가장 좁은 실행 가능 검사 고르기** (직접) — 그 코드 경로에 이미 쓰이는 단위·컴포넌트·통합·회귀 테스트 중 가장 가까운 것. 실용적인 테스트 경로가 안 보이면 절차를 채우려고 새로 만들지 않는다.
3. **실패 테스트 작성 — Codex 위임 1**
   `codex e --skip-git-repo-check -s workspace-write "<테스트 파일 경로>에 <버그>를 잡는 테스트 하나만 추가. 기대 동작: <...>. 운영 코드는 건드리지 마라." < /dev/null`
   → `git diff` 로 검수: 테스트 파일만 바뀌었는지, 현재 구현을 따라 쓰지 않고 **의도된 동작**을 표현하는지.
4. **고치기 전 실행** (직접) — 새 테스트를 내가 돌려 **의도한 이유로** 실패하는지 확인한다. 통과하거나 엉뚱한 이유로 실패하면 구현을 건드리기 전에 테스트·재현을 고친다(구체 지시로 Codex 재위임).
5. **버그 수정 — Codex 위임 2**
   `codex e --skip-git-repo-check -s workspace-write "<운영 코드 파일 경로>의 <원인>을 고쳐 <테스트 이름>이 통과하게 하라. 테스트는 고치지 마라. 주변 계약(<...>)은 유지." < /dev/null`
   → `git diff` 검수: 가장 작은 변경인지, 테스트를 건드리지 않았는지, 과잉 변경·회귀가 없는지.
6. **고친 뒤 재실행** (직접) — 회귀 테스트가 통과하는지, 주변 테스트도 깨지지 않았는지 내가 돌린다. 결함이 있으면 직접 고치지 않고 구체 지시로 재위임.

## 실패 테스트가 비현실적일 때

가장 가까운 실행 가능 회귀 검사를 쓴다: 대상 스크립트, 수동 재현 명령, 브라우저 자동화, 스냅샷 비교, 로그 단언, 좁은 통합 검사. 프로젝트에 검증 경로가 없으면 `create-verification-skill`.

나쁜 테스트보다 테스트 없음이 낫다. 나쁜 테스트란: 대부분 mock 을 시험하는 것, 현재 구현 세부를 박아 넣은 것, 타이밍·무관한 전역 상태에 기대는 것, 작은 수정에 비싼 인프라가 드는 것, 수정 증명 직후 지울 것.

## 가드레일

- 틀린 구현에 맞추려고 테스트를 바꾸지 않는다.
- 기대 동작이 진짜 바뀌었고 이유가 분명할 때만 기존 단언을 약하게 한다.
- 회귀 테스트는 그 버그에 집중한다. 넓은 fixture 변경이나 무관한 커버리지 확장을 하지 않는다.
- 간헐적 버그면 가능한 한 결정적으로 만들고, 고정하려는 신호를 적는다.
- 버그가 더 넓은 실패 부류를 드러내면 좁은 회귀 경로를 먼저 반영하고, 형제 커버리지는 그다음에 따로 판단한다.

## 완료 증거 — prove-it-works

결과만이 아니라 증거를 낸다. on_complete result 에 고치기 전·후 실행을 모두 넣는다:

```json
{"proof":[
  {"cmd":"npm test -- auth.spec.ts","exit_code":1,"output":"(고치기 전) Expected 401, received 200"},
  {"cmd":"npm test -- auth.spec.ts","exit_code":0,"output":"(고친 뒤) Tests: 1 passed"},
  {"cmd":"npm test","exit_code":0,"output":"Tests: 84 passed, 84 total"}
]}
```

## 보고 (한국어)

- 고치기 전 실패한 테스트(또는 실행 검사)와 그 실패 내용.
- 고친 뒤 통과한 실행과 함께 돌린 주변 검증.
- 고치기 전 실패를 보이지 못했으면 그 이유와 대신 쓴 가장 가까운 회귀 검사.
