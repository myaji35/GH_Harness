# What did I get done (기간별 한 일 요약)

> 출처: open-pstack `what-did-i-get-done` (MIT, NOTICE.md). GH_Harness 규칙에 맞게 옮김.

정해진 기간에 실제로 끝난 일을 짧고 밀도 있게 정리한다. 읽는 사람은 **비개발자 관점의 대표님**이다.

## 절차

1. **기간을 실제 날짜로 바꾼다.** "지난주" → `2026-10-26 ~ 2026-11-01` 처럼. 모호하면 해석을 한 줄 밝히고 진행한다(묻지 않는다).
2. **범위.** 기본은 현재 저장소. 대표님이 "전체", "모든 프로젝트"라고 하면 `/Volumes/E_SSD/02_GitHub.nosync/*`, `/Volumes/GH_APFS/*` 아래 git 저장소를 훑는다.
3. **커밋 읽기** — 현재 git 사용자 이메일로 작성된 것만, 병합 커밋·미커밋 변경 제외:
   ```bash
   git log --author="$(git config user.email)" --no-merges --since="<시작> 00:00" --until="<끝> 23:59" --pretty='%ad %s' --date=short
   ```
4. **이슈 DB 보강.** `.claude/issue-db/registry.json` 에서 그 기간에 `DONE` 이 된 이슈의 title·result 를 본다(커밋 메시지의 ISS-NNN 과 맞춰 본다). proof 가 있는 이슈는 "확인됨"으로 쓸 수 있다.
5. **종합.** 중요한 결과만 골라 근황 보고로 쓴다.

## 지침

- 아주 짧고 정보 밀도 높게. 쉬운 말로 — "무엇을 바꿨나"가 아니라 **"무엇이 가능해졌나 / 무엇이 고쳐졌나"**.
- 동작·구조가 바뀐 큰 변화를 우선한다. 서식·import·사소한 이름 변경 같은 겉치레는 뺀다.
- 의도나 동기를 추측하지 않는다. 기능적으로 묘사한다.
- 핵심 수치(커밋 수, 끝난 이슈 수, 고친 버그 수 등)는 실제로 센 값만 1~3개.
- 커밋 해시·파일 경로는 대표님이 찾아볼 필요가 있을 때만.

## 출력 (한국어)

- 근황 보고로 쓸 수 있는 짧은 요약 1~2문장 + 핵심 수치
- 실제로 쓴 날짜 범위(와 훑은 저장소)
- 선택: 큰 변화만 2~5개 글머리
