# Show me your work (결정 기록)

> 출처: open-pstack `show-me-your-work` (MIT, NOTICE.md). GH_Harness 규칙에 맞게 옮김.

기록은 하나만 둔다.

## decision-trace.sh 와의 관계 — 보완 (대체 아님)

| | `.claude/hooks/decision-trace.sh` | 이 스킬 |
|---|---|---|
| 누가 쓰나 | hook 이 자동(on_complete·dispatch-ready·sandbox-enforce) | 작업하는 에이전트가 직접 |
| 단위 | 이슈 생애 이벤트(created/dispatched/completed/failed…) | 결정·분기·되돌림·검증 체크포인트 |
| 담는 것 | **언제·무엇이** 일어났나 (ISS-NNN, agent, model, passed) | **왜** 그렇게 했고 **근거**가 무엇인가 |
| 위치 | `.claude/trace/YYYY-MM-DD.jsonl` | `.audit/<ISS-NNN 또는 작업명>.tsv` |

- decision-trace 는 바꾸거나 대신하지 않는다. 이 스킬의 `evidence` 칸에서 trace 줄(`.claude/trace/2026-11-03.jsonl` 의 ISS-NNN completed)이나 이슈 ID 를 가리켜 둘을 잇는다.
- 이슈 단위 작업이면 파일 이름을 이슈 ID 로 한다(`.audit/ISS-123.tsv`). on_complete result 의 `proof` 와 내용이 겹치면 TSV 쪽은 포인터만 둔다.

## 형식

TSV 파일 하나, 결정 하나당 한 줄. 칸은 한 줄로 유지한다. 근거는 산문이 아니라 포인터다.

`references/decision-log-template.tsv`(헤더 행)를 복사해 시작한다. 칸:

- **ts.** ISO8601 시각.
- **phase.** 단계 또는 작업 갈래.
- **decision.** 무엇을 골랐거나 했나, 한 줄.
- **why.** 쉬운 말로 된 이유. 원칙이 이끌었으면 전문용어 태그가 아니라 풀어서.
- **evidence.** 증명하는 링크·경로: 커밋 SHA, PR 번호, `file:line`, ISS-NNN, 산출물·trace·스크린샷 경로. 문단 금지.
- **result.** 결과 또는 판정 상태: `테스트 통과`, `되돌림`, `pixel-diff 0`, `판정 불가`, `열림`.

예시(검토자가 한눈에 읽게 쉬운 말로 — 한국어로 써도 된다):

```
ts	phase	decision	why	evidence	result
2026-05-24T09:02:00Z	frame	시작 전에 작업량부터 셌다, 컴포넌트 약 100개·약 75시간	긴 실행 전에 크기를 알고 싶었다	commit 3a9f1c2	시작 전에 정리할 것 5개 발견
2026-05-24T09:40:00Z	harness	바꾸기 전에 기존 화면 스크린샷을 찍었다	옛것과 새것을 비교해 화면 변화를 잡으려고	scripts/snapshot.sh, baseline/	기준 스크린샷 120장 저장
2026-05-24T11:15:00Z	widget	겉모습은 그대로 두고 위젯 스타일을 옮겼다	변경을 작게, 결과를 동일하게	commit 7c21e0a, pixel-diff 0	똑같이 보임, 테스트 통과
2026-05-24T12:30:00Z	widget	보조 에이전트 작업을 버렸다, 스크린샷이 비어 있었다	요약을 믿지 않고 실제 파일을 확인했다	worktree reset	되돌림, 다음을 위해 지시를 조였다
```

## 한 줄 기록하기

동료에게 한 일을 말하듯 쓴다. 쉬운 말, 구체적 행동, AI 말투·추상 용어 금지.

도우미: `bash scripts/log.sh <logfile> <phase> <decision> <why> <evidence> <result>`. `ts` 를 찍고, 처음 쓸 때 헤더를 쓰고, 칸 안의 탭·줄바꿈을 지우고, `=` `+` `-` `@` 로 시작하는 칸 앞에 작은따옴표를 붙인다(스프레드시트 수식 실행 방지). 그냥 `printf` 로 줄을 덧붙여도 되지만, 칸이 생성·외부 텍스트에서 오면 같은 바이트를 조심한다.

- 하네스 규칙: 이 스킬 폴더의 `log.sh` 는 외부(open-pstack)에서 온 원문 그대로다. **처음 쓰기 전에 파일을 읽어 확인**하고 쓴다. 고쳐야 하면 직접 고치지 않고 Codex 에 위임한다.

모든 행동이 아니라 결정 지점과 체크포인트를 기록한다: 고른 분기, 검증 결과와 함께 끝난 단위, 계기와 함께 한 방향 전환·되돌림, 드러난 막힘, 고친 게이트. 반복 실행이면 반복당 한 줄. 사소하고 자명한 것은 건너뛴다.

**실행(run)** = 에이전트 대화 하나(이후 턴과 그 요약 포함). 이어받기·교체 에이전트·새 대화는 새 실행이다. 이미 줄이 있는 기록에 덧붙일 때 그 실행의 첫 줄은 phase `start` 이고, 다른 실행의 `start` 줄 뒤 첫 줄도 그렇다. 그래서 나중 턴에 돌아온 실행은 먼저 기록의 마지막 줄들을 읽어 다른 실행이 그사이 썼는지 본다. `start` 줄은 이 실행이 쓰지 않은 앞 줄들의 `ts` 범위를 적고, evidence 에 이 실행(세션 id 등)을 적는다. `start` 는 다른 용도로 쓰지 않는다.

## 어디에 두나

기본은 커밋하지 않는 작업 산출물이다. 작업 폴더의 `decisions.tsv`, 여러 작업이 동시에 돌면 `.audit/<ISS-NNN 또는 작업명>.tsv`. git 에서 뺀다(`.gitignore` 에 `.audit/` 가 없으면 추가는 Codex 위임 또는 대표님 커밋 때 함께).

검토자가 기록을 봐야 결과를 믿을 수 있을 만큼 큰 작업일 때만 커밋한다.

## 규칙

- 덧붙이기만. 틀린 결정은 그것을 대체하는 새 줄로 남긴다. 이력을 고치거나 지우지 않는다.
- 손으로 만든 일회성보다 커밋된 스크립트가 만든 근거를 선호한다(테스트·검증 스크립트 출력, on_complete `proof`).

## 기록을 transcript 와 대조하기

실행 끝, 넘기기 전에 기록이 사실을 말했는지 확인한다. 이 실행의 transcript 를 `~/.claude/projects/<encoded-cwd>/` 에서 읽는다. `~/.claude/projects/` 전체를 glob 하지 않는다 — 관계없는 사적 대화를 읽게 된다. 이 실행의 줄(이 실행의 `start` 줄부터, 또는 이 실행이 기록을 만들었으면 첫 줄부터, 다른 실행의 다음 `start` 줄까지)을 실제 일어난 일과 맞춰 본다:

- 모든 줄이 실제 결정·행동에 대응하는가.
- 각 줄의 근거가 실제로 열리고 줄이 주장하는 것을 보여 주는가.
- 작업을 좌우했는데 기록 안 된 분기·전환·포기한 접근은 빈틈이다. 추가한다.

이야기가 아니라 기록을 바로잡는다. 대조는 줄을 고치거나 지우지 않는다(지어낸 줄도). 실제 결정·행동이 아니거나 주장·근거가 틀린 줄은 실제 일어난 일과 열리는 포인터로 대체하는 줄을 추가한다. 이 실행 범위 밖 줄은 확인하지 않는다. 단 이 실행의 작업이 그중 하나가 틀렸음을 보이면 틀린 결정처럼 대체한다.

## 다른 모델의 기록 검토

넘기기 전에 작업한 모델과 **다른 모델 계열**로 기록을 검토한다. 자기 검토는 대신할 수 없다(하네스 v6 교차 검증 정책과 같다). 하네스에서는 Codex 를 쓴다:

```bash
codex e --skip-git-repo-check -s read-only "<.audit/ISS-NNN.tsv 와 이 실행 transcript 경로>를 읽고, 대표님이 주의해야 할 것을 찾아라: 근거가 약하거나 없는 결정, transcript 에 증거 없이 주장된 검증, 돌아보면 위험한 선택(성급함·범위 확장·증상 덮기), 대충 훑으면 놓칠 빈틈. 작업을 다시 하지 말고 줄 번호·시점을 짚어 목록으로만 답하라." < /dev/null
```

Codex 를 쓸 수 없으면(`which codex` 실패·로그인 없음) 검토자 탈락으로 적고, 같은 모델로 몰래 대체하지 않는다.

기록을 남긴 실행의 답변은 모두 **"주의"** 절로 끝난다. 첫 줄에 검토 모델(`검토: codex <모델>` 또는 `검토자 탈락: <이유>`), 그다음 특정 줄·시점을 가리키는 지적 목록. "지적 없음"도 유효한 값이다. 모델 이름은 생략하지 않는다.

## 기록 검토하는 법

위에서 아래로 읽고, 근거 포인터를 따라가고, 표본을 찍어 확인한다. GitHub 는 커밋된 TSV 를 표로 보여 준다. 터미널에서는 `column -s$'\t' -t decisions.tsv`.

## 다른 스킬과 조합

다른 스킬은 감사 기록을 새로 만들지 말고 이 스킬로 보낸다. 이름으로 참조하고 형식은 이 스킬에 맡긴다. 칸을 다시 적지 않는다.
